## 什么信息放在哪里

- 决策记录保存“确定了什么、为什么、谁确认、适用于哪里”；被新决定替代时标记原条目并链接新条目。
- 规格和运维文档保存当前行为、操作步骤和验收要求，避免把整段实现说明复制到多个入口。
- Issue/PR 保存一次变更的范围、讨论和结果；持久的项目约定应同时更新对应正文。
- `.local/` 和外部控制目录保存命令日志、状态、原始证据及本机工作树位置。它们不是新克隆能读取的项目文档。

## 任务收尾

主机操作者检查本次是否新增或改变决策、规格、运行方法或验收方式，更新相应正文和索引，并确认文档路径可用。简单改动无需新增一份报告；没有新决策时不要制造记录。

保存文件、Git 提交、发布至远端、安装至运行环境是不同状态，应据实说明。安装器会携带项目入口、决策和验收文档，文档内容也参与安装版本指纹。安装目录是只读快照，正文仍应在源码工作树修改。

安装包内的项目入口还链接站点专项文档；这些正文在源码仓库中维护，不作为控制器依赖全部复制。安装快照并不会把未提交的文档自动传给后续克隆的 Issue 工作区；新工作区能否读取新规则仍取决于所用源码提交。文档里的约定不会扩大某个 Issue 已批准的修改范围或权限。
